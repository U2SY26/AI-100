## 📋 핵심 규칙 (Core Rules)

### 규칙 1: Git 워크플로우
**각 단계별 완료 시 자동 Git 커밋, 푸시, 메인 머지**

```bash
# 작업 흐름
1. 작업 브랜치 생성/전환
2. 작업 수행
3. 작업 완료 시:
   - git add .
   - git commit -m "[단계명] 작업 내용"
   - git push origin [작업-브랜치]
   - git checkout main
   - git merge [작업-브랜치]
   - git push origin main
   - git checkout [작업-브랜치]  # 원래 브랜치로 복귀
```

**적용 시점**:
- ✅ 각 TODO 항목 완료 시
- ✅ Phase/Sprint 완료 시
- ✅ 중요 마일스톤 도달 시

### 규칙 2: 호환성 및 에러 체크
**각 단계별 작업 완료 시 품질 보증 프로세스**

```bash
체크리스트:
1. [x] 직전 작업과의 호환성 확인
2. [x] 연관된 파일/모듈과의 통합 테스트
3. [x] 오류 가능성 분석
4. [x] 실제 에러 발생 여부 확인
5. [x] 모든 확인 완료 후 [x] 표시 및 보고
```

**확인 항목**:
- 의존성 충돌 여부
- 파일 경로 정합성
- API 호환성
- 버전 충돌
- 기존 기능 영향도

**보고 형식**:
```
✅ [작업명] 완료
- 호환성 체크: [x] 통과
- 에러 확인: [x] 없음
- 통합 테스트: [x] 성공
- 문서화: [x] 완료
```

## 🔄 워크플로우 상세

### Phase → Sprint → Task 구조

```
Phase (대단위 목표)
└── Sprint (중단위 작업 묶음, 1-2시간)
    └── Task (소단위 작업, 10-30분)
```

### 작업 단계별 체크리스트

#### 1. 작업 시작 시
- [ ] .claude/rules.md 확인
- [ ] 현재 Phase/Sprint/Task 파악
- [ ] 작업 브랜치 생성/전환
- [ ] 작업 시작 시간 기록

#### 2. 작업 수행 중
- [ ] TodoWrite로 진행 상황 추적
- [ ] 중간 체크포인트마다 상태 업데이트
- [ ] 문제 발생 시 즉시 문서화

#### 3. 작업 완료 시
- [ ] 호환성 체크 실행
- [ ] 에러 확인 실행
- [ ] 테스트 실행
- [ ] 문서 작성 (docs 폴더)
- [ ] Git 커밋 & 푸시
- [ ] Main 브랜치 머지
- [ ] 작업 브랜치로 복귀
- [ ] 완료 보고
